# קליטת טפסי התחייבות – המעבדה המרכזית לנגיפים

הלקוח (ממשק המשתמש) של מערכת קליטת טפסי התחייבות. הלקוח לא שומר נתונים: כל המידע מגיע משרת הפייתון בבקשות, ונשאר רק בזיכרון של הדף עד היציאה.

הלקוח מדבר עם השרת רק לפי [חוזה ה-API](docs/api-contract.md).

## הרצה

דרוש Node.js 20 ומעלה.

```bash
npm install
cp .env.example .env      # ב-Windows: copy .env.example .env
npm run dev
```

הממשק נפתח בכתובת http://localhost:5173.

## שרת מדומה או שרת אמיתי

ב-`.env` יש שתי הגדרות:

| הגדרה | מה היא עושה |
|---|---|
| `VITE_USE_MOCK=true` | הלקוח עונה לעצמו עם שרת מדומה ונתונים מדומים. הסיסמה: `demo` |
| `VITE_USE_MOCK=false` | כל בקשה נשלחת לשרת הפייתון |
| `VITE_API_URL` | כתובת שרת הפייתון, למשל `http://localhost:8000` |

**מעבר לשרת הפייתון:** מגדירים `VITE_USE_MOCK=false` ואת `VITE_API_URL`, ומפעילים מחדש את `npm run dev`. בזמן פיתוח Vite מעביר כל בקשה ל-`/api` לשרת, כך שהדפדפן רואה כתובת אחת ועוגיית הכניסה עובדת בלי CORS.

**בשרת המדומה:** הנתונים מתאפסים בכל רענון של הדף. קובץ ששמו מכיל `fail` או `נכשל` ייכשל בכוונה, כדי לבדוק את מצב השגיאה.

## הפצה

```bash
npm run build
```

התוצאה בתיקייה `dist/`. מומלץ ששרת הפייתון יגיש אותה מאותה כתובת של ה-API (או שיעמדו מאחורי אותו reverse proxy), ב-HTTPS בלבד. פרטים בחוזה, בפרק "אבטחה".

## לוגו

הלוגו הרשמי נכנס לתיקייה `assets/` בשם `logo.svg` או `logo.png`, כמו שהוא. הממשק מזהה אותו אוטומטית.

## מבנה

```
docs/api-contract.md   חוזה ה-API מול שרת הפייתון
src/api/               טיפוסים, חיבור לשרת ובקשות
src/mocks/             השרת המדומה (פועל רק כש-VITE_USE_MOCK=true)
src/components/        רכיבים משותפים
src/pages/             מסכים
src/styles/            צבעים, גופנים ועיצוב
src/lib/               עזרים: תאריכים, ספרת ביקורת
assets/                הלוגו הרשמי
```
