# חוזה API – לקוח קליטת טפסי התחייבות

**גרסה 2.2 · 20.10.2026**

המסמך מגדיר את כל הבקשות שהלקוח שולח לשרת הפייתון, ואת ההודעות שהשרת שולח ללקוח ב-WebSocket. הלקוח בנוי לפי המסמך הזה, והשרת המדומה (`src/mocks/`) מממש אותו אחד לאחד. כשהשרת האמיתי יממש את אותן בקשות, משנים בלקוח רק את הכתובת.

ההגדרות המדויקות של המבנים נמצאות גם ב-[`src/api/types.ts`](../src/api/types.ts).

### מה השתנה בגרסה 2.2

- `Upload`: נוסף `thumbnail_url`, ובקשה חדשה `GET /api/uploads/{id}/thumbnail`: תמונה מוקטנת של העמוד הראשון. הלקוח מציג אותה בתור הקליטה, למשל כשצילום מגיע מהטלפון והמחשב לא מחזיק את הקובץ.

### מה השתנה בגרסה 2.1

- `FormSummary`: נוסף `commitment_number`, מספר ההתחייבות. זה המזהה של הטופס, והוא מוצג ראשון בכל מקום. הלקוח משתמש בו גם לזיהוי טופס שנקלט פעמיים.

### מה השתנה מגרסה 1

- **"קובץ" (Upload) נפרד מ"טופס" (Form).** קובץ אחד, למשל PDF סרוק, יכול להכיל כמה טפסים. השרת מפצל אותו, ולכל טופס יש `upload_id` ו-`upload_pages`.
- **העלאה:** `POST /api/uploads` במקום `POST /api/forms`. התשובה היא `202`, והעיבוד נעשה בתור.
- **עדכונים חיים:** WebSocket בכתובת `/api/live` במקום בדיקה חוזרת.
- **צילום מהטלפון:** `POST /api/capture/{token}/uploads` במקום `.../forms`.
- `FormSummary`: נוספו `upload_id` ו-`upload_pages`, וירדו `file_type` ו-`file_sha256` (הם עכשיו ב-Upload).

## כללי

- כל הכתובות מתחילות ב-`/api`.
- גוף הבקשות והתשובות ב-JSON בקידוד UTF-8, חוץ מהעלאת קבצים (multipart) ותמונות.
- זמנים בפורמט ISO 8601 עם אזור זמן, למשל `2026-10-20T08:14:03Z`. תאריך בלבד: `2026-10-19`.
- מזהים הם מחרוזות.
- כל הבקשות דורשות עוגיית כניסה, חוץ מ-`POST /api/auth/login` ומבקשות הצילום מהטלפון (`/api/capture/...`).

### שגיאות

כל שגיאה מחזירה קוד HTTP מתאים וגוף בצורה הזו:

```json
{ "error": { "code": "bad_password", "message": "הסיסמה שגויה" } }
```

`message` לא חובה. אם הוא חסר, הלקוח מציג הודעה בעברית לפי קוד ה-HTTP. **חשוב:** גם 404 מה-API חייב לחזור בצורה הזו. 404 בלי הגוף הזה הלקוח מפרש כ"הבקשה לא הגיעה ל-API" (כתובת שרת שגויה).

| קוד | מתי |
|---|---|
| 400 | בקשה לא תקינה |
| 401 | אין עוגיית כניסה תקפה, או סיסמה שגויה |
| 404 | הפריט לא קיים |
| 409 | הפעולה לא מתאימה למצב הנוכחי, או קובץ כפול |
| 410 | סשן הצילום פג |
| 413 | קובץ גדול מדי |
| 415 | סוג קובץ לא נתמך |
| 429 | יותר מדי ניסיונות כניסה |

## אבטחה – דרישות מהשרת

- **HTTPS בלבד** בסביבה אמיתית (וב-WebSocket: `wss://`).
- **אותו מקור:** עדיף שהשרת יגיש גם את קבצי הלקוח (`dist/`) או שיעמוד מאחורי אותו reverse proxy, כך שאין צורך ב-CORS. בזמן פיתוח, Vite מעביר את `/api` (כולל ה-WebSocket) לשרת.
  אם בכל זאת הלקוח והשרת בכתובות שונות: CORS עם כתובת מפורשת (לא `*`), `Access-Control-Allow-Credentials: true`, ועוגייה עם `SameSite=None; Secure`.
- **עוגיית כניסה:** `HttpOnly; Secure; SameSite=Strict; Path=/api`, תוקף של 8 שעות.
- **סיסמה:** נשמרת ב-`.env` של השרת. השוואה בזמן קבוע (`hmac.compare_digest`) והגבלת ניסיונות.
- **WebSocket:** בודקים את עוגיית הכניסה בזמן ה-handshake, **ובודקים שכותרת `Origin` היא הכתובת של הלקוח** (הגנה מפני Cross-Site WebSocket Hijacking). בלי כניסה תקפה סוגרים עם קוד `4401`.
- **בלי מטמון:** כל תשובה עם נתונים אישיים או תמונה נשלחת עם `Cache-Control: no-store`. הלקוח לא שומר נתונים בדפדפן.
- **בדיקת קבצים לפי התוכן** (magic bytes) ולא לפי הסיומת. גודל מרבי: 25MB.
- **לא לכתוב ללוג** שמות, מספרי ת"ז, ערכי שדות או תוכן קבצים.

## ארכיטקטורה מומלצת בצד השרת

```
דפדפן ──HTTPS──▶ API ──▶ תור (Redis) ──▶ עובדים (Gemini, Qwen, ספרת ביקורת)
   ▲                                           │
   └────── WebSocket /api/live ◀── Redis pub/sub ◀──┘
```

- ה-API רק שומר את הקובץ, מכניס משימה לתור ועונה מיד `202`. כך הוא לא נתקע גם כשמגיעים מאות קבצים יחד.
- מספר העובדים קובע כמה קריאות למודלים רצות במקביל (שמירה על מגבלות הקצב).
- משימה שנכשלה בגלל קריסה חוזרת לתור ולא הולכת לאיבוד.
- העובדים רצים בתהליך נפרד, ולכן הם מפרסמים כל שינוי בערוץ Redis pub/sub, ותהליך ה-API מעביר אותו לכל חיבורי ה-WebSocket.

## מבני נתונים

### Upload – קובץ שנשלח

```json
{
  "id": "u_31",
  "file_name": "סריקה_יומית.pdf",
  "file_type": "application/pdf",
  "file_size": 4823100,
  "file_sha256": "9f2c4a…",
  "source": "upload",
  "status": "processing",
  "received_at": "2026-10-20T09:14:02Z",
  "updated_at": "2026-10-20T09:14:31Z",
  "page_count": 12,
  "form_count": 4,
  "form_ids": ["f_101", "f_102", "f_103", "f_104"],
  "queue_position": null,
  "eta_at": "2026-10-20T09:15:40Z",
  "thumbnail_url": "/api/uploads/u_31/thumbnail",
  "error": null
}
```

| שדה | הסבר |
|---|---|
| `source` | `upload` (גרירה או הדבקה), `phone` (צילום מהטלפון), `demo` (מצב הדגמה) |
| `status` | ראו הטבלה למטה |
| `page_count` | מספר העמודים בקובץ. `null` עד שהשרת קרא אותו |
| `form_count`, `form_ids` | כמה טפסים נמצאו ומה המזהים שלהם. `null` ו-`[]` עד סוף הפיצול |
| `queue_position` | רק בסטטוס `queued`: כמה קבצים לפניו בתור (1 = הבא בתור) |
| `eta_at` | מתי צפוי להסתיים העיבוד של **כל** הקובץ. לא חובה, אבל מומלץ מאוד |
| `thumbnail_url` | כתובת התמונה המוקטנת של העמוד הראשון. `null` עד שהיא מוכנה (או אם אי אפשר להכין אותה) |
| `error` | רק ב-`failed`: הסבר קצר בעברית פשוטה |

**חישוב `eta_at` מומלץ:** `עכשיו + (טפסים שנשארו ÷ מספר עובדים) × זמן ממוצע לטופס`, כשהזמן הממוצע הוא ממוצע נע על הטפסים האחרונים. לפני הפיצול אפשר להעריך לפי מספר העמודים.

#### סטטוס קובץ

| ערך | בעברית | מתי |
|---|---|---|
| `queued` | נשלח לעיבוד | הקובץ נשמר וממתין בתור |
| `splitting` | מפצל לטפסים | עובד קורא את הקובץ ומחלק אותו לטפסים |
| `processing` | בעיבוד | הטפסים נוצרו, והחילוץ רץ עליהם |
| `done` | הסתיים | כל הטפסים הגיעו ל-`pending_review` או ל-`failed` |
| `failed` | נכשל | הקובץ עצמו לא נקרא (פגום, ריק, מוצפן). כשל של טופס בודד לא מכשיל את הקובץ |

### סטטוס טופס

| ערך | בעברית | הערה |
|---|---|---|
| `received` | התקבל | הטופס נוצר בפיצול |
| `processing` | בעיבוד | החילוץ רץ |
| `pending_review` | ממתין לבדיקה | גם כשאין שדות צהובים, אדם מאשר |
| `approved` | אושר | |
| `failed` | נכשל | `error` מסביר למה |
| `rejected` | נדחה | כולל טופס שמוזג לטופס אחר |

### FormSummary – שורה ברשימה

```json
{
  "id": "f_102",
  "upload_id": "u_31",
  "upload_pages": [4, 5, 6],
  "file_name": "סריקה_יומית.pdf",
  "source": "upload",
  "status": "pending_review",
  "received_at": "2026-10-20T09:14:02Z",
  "updated_at": "2026-10-20T09:14:41Z",
  "reviewed_at": null,
  "commitment_number": "633679458",
  "person_name": "נועה לוי",
  "id_number": "123456782",
  "form_date": "2026-10-19",
  "page_count": 3,
  "uncertain_count": 2,
  "corrected_count": 0,
  "progress": null,
  "error": null,
  "merged_into": null
}
```

| שדה | הסבר |
|---|---|
| `upload_id` | הקובץ שממנו הטופס הגיע |
| `upload_pages` | אילו עמודים בקובץ המקורי שייכים לטופס (מתחיל ב-1) |
| `file_name`, `source`, `received_at` | מועתקים מהקובץ, לתצוגה ולחיפוש |
| `reviewed_at` | מתי אושר או נדחה. משמש לחישוב זמן טיפול ממוצע |
| `commitment_number` | מספר ההתחייבות, מתוך השדה המתאים בטופס. המזהה הראשי של הטופס. `null` עד סוף החילוץ |
| `person_name`, `id_number`, `form_date` | ערכים מתוך השדות, לחיפוש ולזיהוי כפילויות. `null` עד סוף החילוץ |
| `page_count` | מספר העמודים **בטופס** |
| `uncertain_count` | כמה שדות צהובים עדיין פתוחים |
| `corrected_count` | כמה שדות תוקנו ידנית. 0 באישור = "אושר בלי תיקון" |
| `progress` | רק בזמן `received`/`processing`, לא חובה: `{ "percent": 60, "step": "אימות שני (Qwen)" }` |
| `error` | רק ב-`failed`: הסבר קצר בעברית פשוטה |
| `merged_into` | מזהה הטופס שאליו מוזג הטופס הזה |

### FormDetail – טופס מלא

כל השדות של `FormSummary`, ובנוסף:

```json
{
  "pages": [
    { "number": 1, "width": 1240, "height": 1754, "image_url": "/api/forms/f_102/pages/1/image" }
  ],
  "fields": [ /* Field */ ]
}
```

`pages` ממוספרים בתוך הטופס (1, 2, 3…), לא לפי הקובץ המקורי. `fields` מגיע בסדר שבו השדות מופיעים בטופס.

### Field – שדה

```json
{
  "key": "id_number",
  "label": "תעודת זהות",
  "type": "id_number",
  "value": "123456782",
  "confidence": 0.62,
  "uncertain": true,
  "reason_code": "models_disagree",
  "reason": "Gemini קרא 123456782 ו-Qwen קרא 123456732",
  "readings": { "gemini": "123456782", "qwen": "123456732" },
  "box": { "page": 1, "x": 0.12, "y": 0.30, "w": 0.20, "h": 0.04 },
  "corrected": false,
  "original_value": null
}
```

| שדה | הסבר |
|---|---|
| `key` | מזהה קבוע של השדה, באנגלית |
| `label` | שם השדה בעברית, כפי שיוצג |
| `type` | `text`, `id_number`, `date`, `phone`, `number`, `checkbox`, `signature`. משפיע על התצוגה בלבד |
| `confidence` | 0 עד 1. לא חובה |
| `uncertain` | `true` = שדה צהוב |
| `reason_code` | `models_disagree`, `checksum_failed`, `illegible`, `missing`, `low_confidence`, `other` |
| `reason` | משפט קצר בעברית שמוצג ליד השדה הצהוב |
| `readings` | מה כל מודל קרא. הלקוח מציג כפתור בחירה לכל קריאה. לא חובה |
| `box` | איפה השדה כתוב בטופס. לא חובה: בלעדיו מוצגת התמונה המלאה בחלונית מתקפלת |
| `corrected` | `true` אם הערך הנוכחי שונה מהמקורי |
| `original_value` | הערך שהחילוץ החזיר, נשמר בתיקון הראשון. `null` אם לא תוקן |

**קואורדינטות (`box`):** `x`, `y` הם הפינה העליונה השמאלית, ו-`w`, `h` הם הרוחב והגובה. כולם חלק יחסי מגודל העמוד, בין 0 ל-1, כך שלא משנה באיזו רזולוציה התמונה. `page` הוא מספר העמוד **בתוך הטופס**, מתחיל ב-1.

Gemini מחזיר `box_2d` בצורה `[ymin, xmin, ymax, xmax]` בסקאלה 0–1000. ההמרה:

```python
ymin, xmin, ymax, xmax = box_2d
box = {"page": 1, "x": xmin / 1000, "y": ymin / 1000,
       "w": (xmax - xmin) / 1000, "h": (ymax - ymin) / 1000}
```

## בקשות

### כניסה

#### `POST /api/auth/login`

```json
{ "password": "..." }
```

- `204` ועוגיית כניסה (`Set-Cookie`).
- `401` סיסמה שגויה. `429` יותר מדי ניסיונות.

#### `POST /api/auth/logout`

`204`. מוחק את העוגייה ומנתק את חיבורי ה-WebSocket של הסשן.

#### `GET /api/auth/session`

- `200` `{ "authenticated": true }`
- `401` אם אין כניסה בתוקף.

### קבצים (Uploads)

#### `POST /api/uploads`

העלאת קובץ אחד (`multipart/form-data`). הלקוח שולח כל קובץ בבקשה נפרדת, כדי שלכל קובץ יהיה פס התקדמות משלו. אין הגבלה על מספר הקבצים; הלקוח שולח עד 4 במקביל וממשיך עם השאר.

| חלק | חובה | הסבר |
|---|---|---|
| `file` | כן | הקובץ |
| `sha256` | כן | טביעת האצבע שהלקוח חישב (hex, 64 תווים). השרת מאמת אותה מול הקובץ |
| `source` | לא | `upload` (ברירת מחדל) או `demo` |
| `force` | לא | `true` = לקלוט גם אם קובץ זהה כבר נקלט |

- `202` `Upload` בסטטוס `queued`, עם `queue_position`. השרת ממשיך ברקע.
- `409` אם קובץ זהה כבר נקלט ולא נשלח `force`:
  ```json
  { "error": { "code": "duplicate_file", "message": "הקובץ הזה כבר נקלט.",
      "existing_upload": { "id": "u_12", "file_name": "סריקה.pdf", "received_at": "2026-10-19T11:02:00Z" } } }
  ```
- `413`, `415`.

**סוגי קבצים:** PDF, JPEG, PNG, TIFF, HEIC/HEIF, WEBP. PDF ו-TIFF יכולים להכיל כמה עמודים וכמה טפסים.

#### `GET /api/uploads`

`200` `{ "items": [Upload, ...] }`: כל הקבצים מ-24 השעות האחרונות, מהחדש לישן. משמש את מסך הקליטה, ולסנכרון אחרי התחברות מחדש של ה-WebSocket.

#### `GET /api/uploads/{id}`

`200` `Upload`. `404` אם לא קיים.

#### `GET /api/uploads/{id}/thumbnail`

תמונה מוקטנת של העמוד הראשון בקובץ: JPEG, PNG או WEBP, ברוחב של בערך 240 פיקסלים (עד 40 ק״ב).

- מכינים אותה **מיד בקליטה**, לפני הכניסה לתור, כדי שתוצג כבר בזמן ההמתנה. PDF: מרנדרים את העמוד הראשון. תמונה: מקטינים. HEIC/TIFF: ממירים.
- `Cache-Control: no-store`, דורש עוגיית כניסה.
- `404` אם עוד לא מוכנה. הלקוח מבקש אותה רק כש-`thumbnail_url` לא `null`.

#### `POST /api/uploads/{id}/retry`

מכניס שוב לתור קובץ בסטטוס `failed`. `202` `Upload` בסטטוס `queued`. `409` אם הסטטוס אחר.

### טפסים

#### `GET /api/forms`

`200` `{ "items": [FormSummary, ...] }`, מהחדש לישן.

החיפוש, הסינון, המדדים, לוח השנה וזיהוי הכפילויות מחושבים בלקוח מתוך הרשימה הזו. כפילות היא אותו `commitment_number` (אותו טופס) או אותו `id_number` (אותו מטופל) ביותר מטופס אחד שלא נדחה.

#### `GET /api/forms/{id}`

`200` `FormDetail`. `404` אם לא קיים.

#### `GET /api/forms/{id}/pages/{number}/image`

תמונת העמוד כ-PNG או JPEG. השרת ממיר PDF, TIFF ו-HEIC לתמונה שהדפדפן יכול להציג. `Cache-Control: no-store`.

#### `PATCH /api/forms/{id}/fields/{key}`

תיקון שדה או אישור שלו.

```json
{ "value": "123456782", "source": "gemini" }
```

`source`: `manual` (הוקלד ידנית), `gemini` / `qwen` (נבחרה קריאה של מודל), `confirmed` (הערך הנוכחי נכון).

מה השרת עושה:
1. בתיקון הראשון שומר את הערך הקודם ב-`original_value`.
2. מעדכן את `value`, מסמן `uncertain: false`, ו-`corrected` לפי השוואה ל-`original_value`.
3. מעדכן את `uncertain_count` ו-`corrected_count` של הטופס, ושולח `form.updated`.

- `200` `Field` המעודכן.
- `409` אם הטופס לא בסטטוס `pending_review`.

#### `POST /api/forms/{id}/approve`

מאשר טופס בסטטוס `pending_review`. שדות צהובים שנשארו פתוחים נחשבים מאושרים כפי שהם. מעדכן את `reviewed_at`.

- `200` `FormSummary`. `409` אם הסטטוס אחר.

#### `POST /api/forms/{id}/reject`

```json
{ "reason": "כפילות" }
```

`reason` לא חובה. `200` `FormSummary`.

#### `POST /api/forms/{id}/retry`

מריץ שוב את החילוץ לטופס בסטטוס `failed` (בלי לפצל מחדש את הקובץ). `200` `FormSummary` בסטטוס `received`.

#### `POST /api/forms/{id}/merge`

ממזג את הטופס `{id}` לתוך טופס אחר עם אותה ת"ז.

```json
{ "into": "f_12ab", "values": { "phone": "050-1234567" } }
```

- `values`: הערכים שהמשתמש בחר עבור טופס היעד. כל אחד נשמר כמו `PATCH` עם `source: "manual"`.
- הטופס `{id}` עובר ל-`rejected` עם `merged_into`.
- `200` `FormSummary` של טופס היעד.

### עדכונים חיים – WebSocket

#### `GET /api/live` (Upgrade: websocket)

דורש עוגיית כניסה ו-`Origin` תקין. השרת שולח הודעות טקסט ב-JSON; הלקוח לא שולח כלום.

```json
{ "type": "upload.updated", "upload": { /* Upload מלא */ } }
{ "type": "form.updated",   "form":   { /* FormSummary מלא */ } }
```

- **כל הודעה מכילה את האובייקט המלא**, לא רק מה שהשתנה. הלקוח מחליף את העותק שלו.
- **מתי לשלוח:** בכל שינוי של קובץ (סטטוס, מקום בתור, פיצול, `eta_at`) ושל טופס (סטטוס, `progress`, תיקון שדה, אישור, דחייה, מיזוג). כולל שינויים שנעשו ממסך אחר או מהטלפון.
- **לכל המחוברים:** אין משתמשים נפרדים, כולם רואים הכל.
- **סדר:** עדכוני `progress` יכולים להגיע בתדירות של עד פעם בחצי שנייה לטופס.
- **שמירה על החיבור:** השרת שולח ping ברמת הפרוטוקול כל 20–30 שניות (בספריות הנפוצות זה ברירת המחדל).
- **סגירה:** `4401` כשהכניסה פגה או אחרי יציאה. הלקוח יעבור למסך הכניסה.

**התנהגות הלקוח:** אחרי כל התחברות (גם מחדש) הוא טוען שוב את `GET /api/uploads` ו-`GET /api/forms`, כך שהודעות שהוחמצו בזמן ניתוק לא חשובות. בזמן ניתוק הוא בודק את הרשימות כל כמה שניות ומנסה להתחבר מחדש.

### צילום מהטלפון

הטלפון לא נכנס בסיסמה. במקום זה, המחשב פותח סשן צילום ומציג קוד QR עם אישור חד-פעמי.

#### `POST /api/capture-sessions`

דורש עוגיית כניסה.

`201` `{ "token": "…", "expires_at": "2026-10-20T08:24:03Z" }`

- `token` אקראי, לפחות 128 ביט (`secrets.token_urlsafe(32)`).
- תוקף של 10 דקות. בתוך הזמן הזה אפשר לשלוח כמה צילומים.

#### `GET /api/capture/{token}`

הטלפון בודק שהסשן תקף.

- `200` `{ "expires_at": "…" }`
- `404` לא קיים. `410` פג.

#### `POST /api/capture/{token}/uploads`

העלאת צילום מהטלפון (`multipart/form-data`): `file` ו-`sha256`.

- `202` `{ "id": "u_40", "status": "queued" }`. בכוונה בלי נתונים אישיים.
- `404`, `410`, `413`, `415`, ו-`429` אחרי 100 צילומים באותו קוד.
- הצילום כבר מיושר, חתוך ומשופר בטלפון: JPEG ברוחב או בגובה של עד 2400 פיקסלים.

הקובץ נכנס לאותו תור עם `source: "phone"`. המחשב רואה אותו מיד דרך `upload.updated`, ומציג את הצילום לפי `thumbnail_url`.
